# Independent review: solar-support Abaqus reconstruction

This repository provides the reference paper, client requirements and a frozen snapshot of work already performed. It is a review package, not a validated model delivery. The objective is to reproduce the applicable paper results within 10% in Abaqus, under the client's stated scope.

Please form your own interpretation from the original source. Existing model assumptions, result labels and conclusions are material to audit, not established facts.

## Suggested reading order

1. `source/Cigdem_Avci_Karatas_EurasianSciEnTech2020.pdf` — original supplied paper, unchanged.
2. `CLIENT_CONTEXT.md` — client instructions and relevant conversation excerpts.
3. `work/scripts/`, `work/runs/` and `raw_odb_evidence/` — implementation, input decks and numerical evidence.
4. `prior_interpretations/` — previous reasoning and status records, retained for completeness. Assess their claims independently.

`REVIEW_PROMPT.md` is a neutral, ready-to-use review request. No particular explanation or correction is presumed.

## Contents

- `source/`: original paper.
- `work/input_data/`: extracted text, rendered source pages and locally consulted references. Additional papers are separate sources, not replacements for the supplied paper.
- `work/scripts/`: current Python source. Abaqus scripts and ordinary-Python helper scripts are identified in their headers.
- `work/runs/000_baseline` through `024_c125_rounded_r8`: input decks, configuration, metadata, source snapshots, small solver diagnostics, numerical summaries and available images. Each directory is an isolated run.
- `work/run_ledger.csv`: comparison ledger generated by the previous workflow.
- `raw_odb_evidence/`: direct exports from selected elements and nodes in the actual ODB files, with field component labels, element connectivity and coordinates. The exporter describes its selection and is included under `tools/`. These extracts are not the complete ODB field history.
- `prior_interpretations/`: historical assumptions and conclusions. Their presence does not endorse them.
- `SNAPSHOT.json` and `FILE_MANIFEST.json`: source revision, scope and file hashes.

Manifest hashes use the published Git blob bytes, including Git's handling of text line endings; PDF and PNG bytes are unchanged. The manifest excludes itself.

The source project contains completed Abaqus runs. Local Abaqus 2024 and 2018 are available; the client's older-version compatibility requirement must be distinguished from what was actually tested. The `.inp` decks can be read directly; the builder and run scripts preserve source detail.

## Snapshot boundaries

This snapshot ends at run024. A concurrently requested independent review is intentionally excluded so this review can proceed independently. Files from that review will not be added without identifying a new snapshot.

ODBs and other native binary solver/model files are omitted. They can be regenerated from the supplied input decks in a licensed compatible Abaqus installation. Some historical scripts contain relative paths for the original working tree; inspect them before executing. Direct result files and decks remain readable without Abaqus.

Current source snapshots may differ from individual historical build snapshots. Use each run's actual `.inp`, metadata and diagnostics to establish what was solved. A successful solver run or a comparison label alone does not establish validation.

## Review output

Provide an evidence-based assessment of correctness and agreement, clearly separating verified defects, source ambiguity and untested possibilities. Support conclusions with precise repository references and independent calculations where feasible. Do not claim a solver result unless you actually obtained or directly verified it.
